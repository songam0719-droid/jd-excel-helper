# 京东查单回填助手

Windows 桌面自动化工具：在已登录且有查询权限的微信京东快递小程序中查询运单，将姓名、电话、地址写回原 Excel 表格。

支持点击结果确认、有限重试、失败单标记和断点续跑。项目由 AI 辅助开发，运行时使用 C#、Windows UI Automation 和本地文件处理，不调用 AI 模型或消耗模型积分。查询需要微信正常联网。

这是社区项目，与京东、腾讯没有官方关联。仅处理你本人或所在公司获授权查询的数据；工具使用现有登录权限，不提供绕过验证或权限的功能。

## 解决什么问题

把“从表格取运单号 → 打开详情 → 展开收件电话 → 抄写收件信息”的重复操作串起来，并处理业务中常见的异常：

- 按钮已经显示，但网络慢、第一次点击没有响应。
- 单号错误、运单取消，或者没有电子存根。
- 中间停止后，需要继续处理剩下的行。
- 失败单不应让整批任务停下，也不应每次启动都重复卡住。
- 原表已有数据时，需要核对，避免串单或误覆盖。

## 功能

| 功能 | 行为 |
| --- | --- |
| 写回原表 | 从 F 列取运单，向同一行的 B/C/D 列写入姓名、电话、地址 |
| 点击后确认 | 检查页面或号码是否变化，未生效才重新定位并点击 |
| 失败隔离 | 最终失败的运单标红，并在“京东查单状态”列记录原因 |
| 默认跳过坏单 | 再次开始时跳过已完整和已标记不可读的记录 |
| 主动复查 | 勾选“重查不可读单”后允许重新查询，成功后清除标记 |
| 每单保存 | 每完成一单就保存，启动前备份原表 |
| 断点续跑 | 保留完成状态与待写入结果，继续处理未完成记录 |
| 写入校验 | 核对页面运单号及原表姓名、电话前后缀，完整地址不一致不覆盖 |
| 暂停与停止 | F8 暂停/继续，Ctrl+Alt+F9 停止，日志记录停止来源 |

## 快速使用

1. 在本仓库的 **Releases** 下载 `jd-excel-helper-v1.4.0-windows.zip`，完整解压。GitHub 自动生成的 `Source code` 压缩包是源码，需要自行编译。
2. 使用 Windows 10/11，确保已有 .NET Framework 4.8/4.8.1。无需安装 Python。
3. 登录微信，打开京东快递小程序的“查快递”页，只保留一个京东窗口。
4. 关闭待处理的 Excel/WPS 文件，双击 `京东查单工具.exe`，选择原 `.xlsx` 文件和工作表。
5. 首次先运行 3 单并核对。要处理全部，设置“本次数量”为 **0**。
6. 运行期间保持电脑解锁、小程序可见，暂时不要操作鼠标。

完整操作和异常处理见 [使用说明](docs/USAGE.md)。

### 表格结构

第 1 行是表头，第 2 行开始是数据。必须保持列顺序：

| 列 | 用途 |
| --- | --- |
| A | 可保留自己的发货日期等内容 |
| B | 收件人姓名，程序写回 |
| C | 收件手机号，程序写回 |
| D | 收件地址，程序写回 |
| E | 可保留自己的店铺、渠道等内容 |
| F | 京东运单号，程序读取 |
| G 及以后 | 保留原业务内容；失败时在已使用内容右侧追加状态列 |

仅支持 `.xlsx`。F 列运单不能是公式；程序要写入的单元格不能有公式，工作表不能受保护。仓库内 [虚构样例](examples/README.md) 只说明结构，不包含可查询的客户运单。

### 重试与失败标记

“每单额外重试”默认 **1**，表示首次查询失败后最多再完整查询一次。它是每一单的次数，不是整批允许失败的单数。

小眼睛步骤单独检查号码是否仍被隐藏，约 1.8 秒后才允许重点击，最多 6 次、约 15 秒。号码完整即停止点击。控件调用、暂停会影响实际经过时间。

确认当前运单的详情页后，约 6 秒仍无电子存根入口就记为不可读。明确取消且没有存根、或暂无运单信息时，会更早跳过。其他页面有各自的加载等待时间。

不可读状态保存在 `.xlsx` 中，所以复制表格或丢失续跑 JSON 后仍可跳过。程序按状态文字和对应运单号识别，不把原先手工涂红的行当成失败。

## 实际使用与验证

项目使用者反馈：公司在实际业务中每天节省十几个工时。这个数字来自单个团队的使用反馈，取决于订单量和原来的人工流程。

1.4 版本的开发验证包括：

- **49 项自动测试通过**，包含 45 种模拟布局组合。
- 一个本机样本中，4 个正常单全部写入成功，12 个收件字段与历史成功查询记录一致。
- 这 4 单含写回约 **12.25 秒/单**，实际覆盖了首次点击未生效后的自动恢复。
- 实际取消单被标记；重新开始时跳过 4 个完整单和 1 个不可读单，没有发起查询。

网络、微信版本、窗口状态会影响速度和可用性。以上不是所有电脑、所有运单或长期运行的成功率保证。详细范围见 [测试说明](docs/TESTING.md)。

## 从源码构建

在 Windows PowerShell 中进入仓库根目录：

```powershell
.\build.ps1
.\test.ps1
```

构建使用系统 .NET Framework C# 编译器和系统程序集，不从网络下载依赖。程序生成在 `bin/京东查单工具.exe`。本地执行策略如果阻止脚本，请按所在组织的正常方式处理。

`test.ps1` 只运行合成数据与模拟界面的自动测试，不操作微信，不读取业务表格。测试文件写在系统临时目录的 `JdHelperTests/` 下，结束时输出路径。这样可以减少仓库解压目录过深导致的路径长度问题。

## 已知边界

- 依赖特定微信小程序的控件结构，页面大改可能需要适配。
- 验证码、访问限制、登录失效、文件被占用或外部修改等全局问题会停止，处理后再续跑。
- 不会发送消息、联系客户、下单或支付。
- 不包含多机共享任务队列；多台电脑必须各自使用独立表格。
- 使用传统 .NET Framework 文件接口，过长路径可能失败；业务表格和源码建议放在较短的本地路径。
- 只有所选工作表中的京东运单全部填完整且正常结束，才清理续跑 JSON 与运行锁。仍有不可读单时保留。原表和备份保留。
